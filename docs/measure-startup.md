# 启动与歌曲列表刷新耗时测量

本文档说明如何使用项目提供的自动化脚本测量 **MusicApp 从启动到单曲列表首帧排版渲染完成** 的全链路耗时。

## 1. 测量指标定义

| 指标名称 | 字段/标识 | 统计说明 |
|---|---|---|
| **端到端总耗时 (E2E Time)** | `end_to_end_ms` | 从主机端发起 `am start -W` 到 logcat 捕获首个曲目排版完成（`TracksFirstTrackLaidOut`）的绝对耗时。 |
| **系统首帧时间 (TTID / Displayed)** | `system_displayed_ms` | Android 系统 `ActivityTaskManager` 记录的 Activity 绘制上屏首帧时间（`Displayed ...: +...ms`）。 |
| **Compose 单曲排版耗时** | `compose_layout_ms` | Compose 页面内从进入 `TracksScreenRoute` 到首个曲目 item 触发 `Modifier.onGloballyPositioned` 的纳秒级耗时转换。 |
| **首帧后渲染增量耗时 (Delta)** | `delta_ms` | `end_to_end_ms - system_displayed_ms`，反映首帧出现后异步数据库查询与列表项排版的耗时。 |
| **曲目总数** | `track_count` | 当前页面实际加载并渲染的曲目总数。 |

## 2. 脚本使用方法

### Python 脚本（推荐：提供详细统计与自动导出报告）

~~~shell
# 默认执行 5 轮冷启动测试（自动在 benchmark_results/ 下生成新的 .json 和 .txt 报告）
python3 scripts/measure_startup_time.py

# 指定测试 10 轮并指定自定义输出目录
python3 scripts/measure_startup_time.py -n 10 --warmup 2 --output-dir custom_reports/

# 仅在终端查看，不保存结果文件
python3 scripts/measure_startup_time.py --no-save

# 测试温启动（后台切回前台）
python3 scripts/measure_startup_time.py --mode warm -n 5

# 指定目标设备（多设备环境）
python3 scripts/measure_startup_time.py -s emulator-5554
~~~

> 💡 **自动归档与 Git 忽略**：
> 脚本默认将每次运行的明细数据自动保存在项目根目录的 `benchmark_results/` 目录下（如 `startup_20260831_153131_cold_5runs.json` 和对应的 `.txt` 摘要）。该目录已被 `.gitignore` 忽略，不会污染代码仓库。

### Bash 脚本（快速单行执行）

~~~shell
# 默认 5 轮冷启动
./scripts/measure_startup_time.sh

# 自定义轮数与启动模式
./scripts/measure_startup_time.sh 10 cold
~~~

## 4. 注意事项

1. **测试前准备**：请确保目标设备已安装应用（`./gradlew :app:installDebug`），且设备媒体库中存有音乐文件。
2. **权限处理**：脚本默认会在首轮前通过 `pm grant` 授予媒体读取权限，避免由于权限弹窗阻塞启动测量。
3. **数据一致性**：冷启动模式下，每轮测试前脚本均会调用 `am force-stop` 并清理 logcat 缓冲区，保证多轮测试独立性。
