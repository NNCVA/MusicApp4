### 范围与文件边界

- `app/src/main/res/values*/strings.xml`：权限用途、拒绝、设置引导与无障碍文案。

- API 26–32 使用 `READ_EXTERNAL_STORAGE`，API 33+ 使用 `READ_MEDIA_AUDIO`；API 36 继续验证最新目标版本行为。

## W3-02：多卷查询与曲目准入

状态：`TODO`

### 目标

交付遍历全部可用外部存储卷的 MediaStore 查询适配器，以及不依赖平台游标的七格式准入纯逻辑。

### 范围与文件边界

- `app/src/main/java/**/data/mediastore/query/`：卷枚举、投影、Cursor 映射和平台异常封装。
- `app/src/main/java/**/data/mediastore/filter/`：MIME、扩展名、时长与系统音频类型准入。
- `app/src/test/java/**/data/mediastore/filter/`：纯逻辑测试。
- `app/src/androidTest/java/**/data/mediastore/query/`：真实 ContentResolver/MediaStore 测试。

### 实施要点

- 接受 MP3、FLAC、WAV、AAC、M4A、OGG、OPUS 且时长大于 0；MIME 优先，缺失或通用 MIME 才按扩展名兜底，明确冲突以 MIME 为准。
- 排除铃声、闹钟、通知音，保留录音、播客和有声书；单条映射失败形成资源化跳过原因并继续。
- API 29+ 读取 `RELATIVE_PATH`；API 26–28 的 `DATA` 只在适配层用于匹配，不写入数据库、不输出日志。

### 验证

- 本地测试覆盖七格式、大小写扩展名、无 MIME、通用 MIME、冲突 MIME、零时长和系统音频类型。
- API 26 验证 `DATA` 兼容路径；API 33、36 验证多卷投影与 URI 身份映射。

### 完成条件

- 查询结果以“卷名 + MediaStore ID”形成稳定曲目标识，平台差异被限制在适配器内。
- 任一曲目失败不终止查询；整体查询失败以明确错误返回且不产生部分持久化。
