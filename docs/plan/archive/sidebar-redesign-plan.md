# 侧边栏三组卡片改造方案

状态：已实施，待用户进行视觉验收（2026-07-30）

## 1. 对比结论

目标图采用三组悬浮圆角卡片、彩色图标和顶部快捷操作；当前应用采用整高 Material 模态面板、纯文字入口和大面积胶囊选中状态。目标图同时展示了更完整的单曲页标题栏、随机播放入口、封面式曲目行和迷你播放器，但这些页面差异不属于本次修改范围；背景图片、背景颜色和 Aero 效果不参与对比。

## 2. 已确认规格

### 2.1 三档窗口

- `<600 dp`：窗口宽度 `50%` 的推移式侧栏；侧栏展开时，主内容整体向右移动同等距离并由窗口边界裁切，不压缩或重排页面内容。
- 推移进度为 `0–1`：侧栏水平位置为 `-侧栏宽度 × (1 - 进度)`，主内容水平位置为 `侧栏宽度 × 进度`，拖动和开关动画必须同步。
- 主内容可见区域覆盖 `18%` 黑色遮罩，点击遮罩关闭侧栏；遮罩不得覆盖侧栏。
- `600–839 dp`：宽度 `240 dp` 的常驻侧栏，不再使用 Navigation Rail。
- `≥840 dp`：宽度 `256 dp` 的常驻侧栏。
- 三档窗口均使用相同的三组圆角卡片；卡片圆角、内外边距和间距从设计令牌读取。
- 紧凑窗口的三组卡片区域可纵向滚动，并同时避让安全区及底部 `80 dp` 迷你播放器。

### 2.2 三组内容

- 顶部快捷操作：退出、明暗模式、均衡器。
- 媒体浏览入口：单曲、专辑、艺术家、文件夹、播放列表。
- 应用操作入口：Scan row（后续进入独立扫描页面）、播放历史、设置、关于。
- 八个一级入口及其独立返回栈保持不变；Scan row 作为侧边栏操作入口进入独立扫描页面，不改变已有一级业务入口。
- Scan row 进入独立扫描页面；Tracks 页面不提供扫描入口、雷达、同步进度或失败重试。同步状态及结果反馈由应用壳层承载，不依赖 Tracks 页面处于前台。

### 2.3 图标与选中状态

- 每个入口使用有语义描述的彩色矢量图标，顶部快捷操作使用图标按钮。
- 取消当前大面积胶囊选中底色；当前页面通过 Tab 选中语义与清爽视觉呈现，不使用整行胶囊底色或额外侧边条。
- 颜色不作为唯一状态信息；所有点击目标至少为 `48 dp`。
- 中英文文案均来自字符串资源，不按截图语言写死。

### 2.4 顶部快捷操作

- 退出按钮打开三选项对话框：
  - “完全退出”：先持久化播放快照并停止播放服务，再移除应用任务；不清除媒体库、历史、播放列表或设置。
  - “回到桌面”：调用系统任务退后台能力，播放服务和媒体通知继续运行。
  - “取消”：关闭对话框，不改变播放或任务状态。
- 明暗模式按钮按“跟随系统 → 浅色 → 深色”循环，并同步更新设置页使用的同一偏好；Snackbar 显示切换结果。
- 均衡器按钮保持可点击，点击后只显示“均衡器将在后续版本提供”的 Snackbar，不创建页面或路由。

### 2.5 迷你播放器层级

- 侧栏打开时，迷你播放器保持完整窗口宽度，覆盖在侧栏和主内容之上并继续响应操作。
- 业务内容和侧栏滚动区域均为迷你播放器预留 `80 dp` 底部空间。
- Full Player 展开或拖动期间继续禁用紧凑窗口的侧栏手势。
- 迷你播放器不跟随业务页面向右移动，避免其右侧操作按钮被窗口裁切。

## 3. 实施步骤

### 3.1 壳层与窗口策略

- 修改 `WindowLayoutPolicy`：紧凑策略改为 `50%` 推移式侧栏，中等策略保持 `240 dp` 常驻侧栏，展开策略保持 `256 dp`。
- 在 `MusicDimensions` 增加侧栏卡片、选中指示条和中等侧栏宽度令牌，页面不得直接写尺寸。
- 移除紧凑分支中的覆盖式 `ModalNavigationDrawer`，改用同一展开进度驱动侧栏与主内容横向位移；根容器裁切移出窗口的主内容。
- 重构 `AppShell` 的层级：侧栏与可推移业务内容位于下层，`18%` 遮罩只覆盖业务内容，应用级 Player Sheet 位于最上层且不参与横向位移。

### 3.2 导航组件

- 将 `NavigationMenu` 从顶层导航文件拆为可复用的侧栏组件，统一渲染三组卡片。
- 建立稳定的入口展示模型，集中定义路由、顺序、图标、固定图标色和字符串资源。
- 一级入口继续交给 `Navigator` 切换并保留现有返回栈；操作项通过独立回调执行，不伪装成 Route Key。
- 独立扫描页面复用 `TracksSyncController.requestManualSync()`，由其调用 `LibrarySyncCoordinator` 并在成功后清除待同步 revision；结果对话框提升到应用壳层，使任意一级页面都能接收结果。

### 3.3 退出、主题与占位能力

- 为完全退出增加应用内关闭通道，复用播放服务现有的“最终快照写入、清空运行时队列、停止服务”顺序；禁止只调用 `finishAndRemoveTask()` 后遗留播放服务。
- 完全退出在服务收到关闭请求后移除应用任务；回到桌面使用 `moveTaskToBack(true)`，不得停止服务。
- 主题快捷操作调用 `SettingsRepository.setThemeMode()` 使用的同一写入路径。
- 均衡器只进入共享 Snackbar 队列。

### 3.4 资源与可访问性

- 补充中英文退出对话框、主题切换结果、均衡器占位和导航内容描述。
- 图标使用项目内矢量资源；不引入仅为侧栏服务的新图标依赖。
- 三组卡片支持系统字体缩放、纵向滚动、触控目标和 TalkBack 语义。

## 4. 验证

- `WindowLayoutPolicyTest` 覆盖 `<600 dp`、`600–839 dp`、`≥840 dp` 及 `240/256 dp` 宽度。
- 新增紧凑壳层回归测试，覆盖关闭、拖动中点、完全展开三个状态；断言侧栏与主内容使用同一进度、完全展开时主内容位移等于窗口宽度 `50%`，且内容尺寸不变。
- 新增纯逻辑测试覆盖入口分组顺序、主题三态循环、完全退出/回到桌面/取消的动作分发，以及扫描操作不改变当前路由。
- 服务测试验证完全退出先保存快照、再清空运行时队列并停止服务；回到桌面不发送停止命令。
- 人工验收紧凑、中等、展开三档窗口、系统字体 `1.5×`、中英文、侧栏滚动、遮罩点击、Mini 操作和退出三选项。
- 固定门禁按 [`../../verification.md`](../../verification.md) 的分层规则执行，并额外运行本计划约定的 `git diff --check`。

实施结果：三组卡片、退出流程及三档窗口侧栏已经实施；紧凑窗口改为 Material 3 推移式侧栏，固定门禁与推移进度回归测试已通过，最终视觉效果由用户验收。

## 5. 非本次范围

- 不修改单曲页标题栏、随机播放与数量区域、曲目封面和双行元数据布局。
- 不修改迷你播放器自身的封面、标题、艺术家或控制按钮样式，只调整其与侧栏的层级。
- 不实现均衡器功能，不新增“音乐库”或“统计”一级页面。
