# MusicApp 首版实现规格

状态：已制定（2026-07-29）

## 1. 依据与优先级

本规格把已接受的设计盘问转换为可编码、可测试的首版契约。发生表述冲突时，按以下顺序处理：

1. `docs/design/design-review-01` 至 `09`、`11`、`12` 的已接受约束。
2. `docs/CONTEXT.md` 的领域词汇与 `docs/adr/` 的架构决策。
3. 本规格、`docs/plan/implementation-execution-plan.md` 及 `docs/plan/implementation-wave-plan.md`。
4. `AGENTS.md` 的工程约定。

## 2. 交付目标

在现有可编译的单模块 Compose/Navigation 3 空白骨架上，交付一款完全离线的 Android 本地音乐播放器，覆盖 26 项首版需求，并满足以下完成条件：

- 平台基线为 `minSdk 26`、`targetSdk 37`，不为 API 25 及以下提供兼容；使用 Kotlin、Compose、Material 3、Navigation 3、Room、Preferences DataStore、Hilt 与 Media3。
- 媒体库、播放列表、历史、隐藏状态、路径规则和播放快照均有稳定事实来源。
- 本地曲目可完成发现、分类浏览、建队、后台播放、系统控制、歌词展示和状态恢复。
- 手机、平板、折叠屏与 ChromeOS 可缩放窗口具备一致的自适应行为。
- English 与简体中文资源完整，最小 CI 包含分层测试、Lint、Debug 构建和 Android Runtime 集成测试。

## 3. 当前基线

- 仓库只有 `:app` 模块，`minSdk 26`、`targetSdk 37`，Kotlin/JVM 使用 17。
- 已接入 Compose、Material 3、Navigation 3、四套 Light/Dark 主题、动态取色、统一设计令牌与共享加载/空态/错误态；八个一级栈、详情 Route Key、三档自适应壳层及应用级 Player Sheet 已建立。Player Sheet 具备 `80 dp` Mini、Full 三子页、队列跳转/移除、进度与模式控制及自适应歌曲信息查看器，并直接消费 MediaController 的稳定播放状态与分类失败代码显示双语错误文案。
- 专辑、艺术家、跨卷文件夹、歌单与播放历史页面已实现派生查询、排序/筛选（艺术家集合页固定名称升序且无集合页排序，详情页沿用既有排序）、空态、批量业务和播放入口；设置页已接入七类设置、路径规则待同步状态与独立数据管理确认，关于页已离线展示安装包版本、致谢和开源许可。
- 已建立 Hilt Application/Activity/Service 入口、应用级协程作用域、可替换时钟与随机源、平台无关领域模型与纯业务策略、Room v2（七张业务表、同步代次与每卷状态）、Repository/Fake、Preferences DataStore 设置 Repository、MediaStore 多卷查询/准入适配、原子媒体库同步、冷启动/前台自动同步协调、单曲 ViewModel 及 Snackbar 队列。高级元数据与内嵌封面已实现按需读取、修改时间换键、有界内存缓存、同键请求合并及全局二并发限制；MediaLibraryService 已以单一会话状态驱动三种播放模式、原始队列、稳定随机序列、跨轮重生成与队列编辑；手动/自然切歌使用可设置的单播放器淡出淡入，坏文件单轮遍历后停止，Media3 处理音频焦点与私密输出断开，实际播放达 `min(30 秒, 50% 时长)` 后更新 Room 历史，超过 300 ms 的缓冲向 UI 显示。播放快照已在队列/切歌/Seek/暂停/销毁及播放中每 5 秒写入 Room，Media3 Playback Resumption 仅在系统或用户触发时恢复队列与位置；通知仅显示三个主操作，划除后保留快照、清空运行时队列并撤销恢复资格。应用内 MediaController 通过严格命名命令读写，外部可信控制器仅保留基础媒体命令。
- Manifest 已声明分版本音频读取权限，未声明 `POST_NOTIFICATIONS`；Hilt Application、启动 Activity、设置白名单备份规则与运行时权限 Gateway 已接入。
- 一级页面 Aero 与 Full Player 封面混色已接入；前后台、屏幕、省电、低电量和系统动画信号可将动态模式降级为不调度帧的纯色背景，条件解除后恢复用户模式。

所有 Wave 均以“从空白骨架新增能力”为基线，不得把设计文档描述误报为已存在代码。

## 4. 首版范围

### 4.1 范围内

- 七种本地音频格式、MediaStore 同步、目录包含与排除、失效恢复。
- 单曲、专辑、艺术家、文件夹、播放列表、历史与队列。
- 单播放器淡出淡入、三种互斥播放模式、MediaSession 与系统媒体控制。
- 外部 LRC、内嵌 SYLT/USLT、专辑封面与按需高级元数据。
- 自适应导航、主题、明暗模式、Aero、应用语言、设置、关于和离线许可。

### 4.2 范围外

- 在线歌词、联网统计、崩溃上传、音频上传及 `INTERNET` 权限。
- 物理删除音频、编辑音频标签、播放列表或播放队列拖拽排序。
- TV、Android Auto、XR 专用界面；保留标准 MediaSession 系统控制。
- 双播放器重叠式交叉淡化、在线媒体流、云同步。

## 5. 架构契约

### 5.1 模块与包依赖

首版保持单一 `:app` 模块，内部依赖方向固定为：

```text
feature/* -> core/designsystem
feature/* -> core/domain
feature/* -> data repository interfaces
data/* -> Room / DataStore / MediaStore adapters
media/* -> domain + repository interfaces + Media3
app shell -> feature entry points + media controller facade
```

- 功能包之间不直接访问彼此的数据实现。
- Composable 只观察 `StateFlow<UiState>` 并调用 `onAction`。
- 一次性 Snackbar、导航结果等通过 `SharedFlow<UiEffect>` 发出。
- Repository 隔离 Room、DataStore、MediaStore；平台对象必须可由 Fake 替换。
- 只有 `MediaLibraryService` 持有 ExoPlayer 与 MediaSession；Activity 和 ViewModel 只依赖 MediaController 门面。

### 5.2 依赖注入

- Hilt 创建 Application、Room、DAO、Repository、扫描器、MediaLibraryService、MediaController 门面和 ViewModel。
- 数据库、设置仓库和媒体控制连接使用与生命周期匹配的单例或进程级作用域。
- 测试通过替换绑定使用 Fake；仅在平台对象无法替换时使用 MockK。

## 6. 数据契约

### 6.1 Room

| 表 | 身份与约束 | 责任 |
|---|---|---|
| `tracks` | “存储卷名 + MediaStore ID”复合主键；标题、Artist ID、Album ID、添加时间、时长、相对路径建索引 | 媒体库事实来源与可用状态 |
| `playlists` | 规范化名称忽略大小写唯一 | 播放列表元数据 |
| `playlist_tracks` | “播放列表 + 曲目”唯一，位置唯一 | 非重复曲目关系与加入顺序 |
| `play_history` | 每个曲目最多一条 | 最近播放时间与累计次数 |
| `hidden_tracks` | 曲目标识唯一 | 隐藏状态 |
| `path_rules` | 目录规则身份唯一 | 包含与排除目录 |
| `playback_snapshot` | 单一活动快照 | 原始队列、随机序列、当前项、位置、播放模式与播放实例计时 |

- 专辑、艺术家、文件夹均从 `tracks` 查询派生。
- 扫描合并、批量操作和播放列表位置写入使用 Room 事务。
- 每个数据库版本导出 Schema，提供逐版本和跨版本 Migration 测试；禁止 destructive migration。

### 6.2 Preferences DataStore

DataStore 只保存用户设置：

- 颜色来源、预设主题、明暗模式、应用语言。
- Aero 模式、淡出淡入总时长。
- 扫描模式“扫描全部／仅扫描指定目录”。

包含和排除目录保存在 Room。重置配置恢复 DataStore 默认值及“扫描全部”，保留 Room 中暂时不生效的路径规则、媒体库、播放列表、历史和播放快照。

### 6.3 歌单名称

- 去除首尾空白后执行 Unicode NFC 规范化。
- 长度按规范化后的 Unicode code point 数计算，允许 `1–50`。
- 重名比较忽略大小写；展示去除首尾空白后的名称。
- 集合默认按创建时间倒序；列表内曲目按加入位置排序，批量添加保持选择顺序。
- 同一列表内重复曲目跳过，并反馈实际新增数与跳过数。
- “播放全部”按加入位置建立新队列，跳过不可用曲目并反馈数量；空列表或没有可用曲目时不替换现有队列。
- 首版不提供歌单曲目拖拽排序。

## 7. 媒体库规格

### 7.1 权限与准入

- Android 13+ 请求 `READ_MEDIA_AUDIO`；API 26–32 请求 `READ_EXTERNAL_STORAGE`。
- 不声明或请求 `POST_NOTIFICATIONS`。
- 前台播放服务声明 `FOREGROUND_SERVICE` 与 `FOREGROUND_SERVICE_MEDIA_PLAYBACK`。
- 首次进入媒体库先展示用途说明；拒绝后不在每次启动重复请求，永久拒绝时引导系统设置。
- 无权限时仍可进入设置与关于。
- 仅接受 MP3、FLAC、WAV、AAC、M4A、OGG、OPUS 且时长大于 0。
- 优先按 MIME 类型判定；MIME 缺失或为通用值时按扩展名兜底，明确冲突时以 MIME 为准。
- 排除铃声、闹钟、通知音，保留录音、播客和有声书。

### 7.2 路径与存储卷

- 查询所有可用外部存储卷。
- API 29+ 使用 `RELATIVE_PATH`；API 26–28 只在扫描适配层读取 `DATA`，禁止写入和记录完整路径。
- “扫描全部”和“仅扫描指定目录”互斥，排除规则始终优先。
- 卷卸载、权限丢失或查询整体失败时保留曲目及关联并标记不可用；重新发现相同身份后恢复。
- 已挂载存储卷完成一次成功的完整同步后，仍未发现的曲目判定为缺失曲目，并从媒体库及播放列表关系、历史、隐藏状态和播放快照引用中直接移除。
- 专辑按“存储卷 + MediaStore Album ID”分组，艺术家按 MediaStore Artist ID 分组且不拆分合作标签；艺术家集合页固定按名称升序且不提供集合页排序，详情页沿用既有排序。
- 文件夹页展示按存储卷划分的真实目录树；`relative_path` 规范为无首尾斜杠的目录值，根目录为空字符串，递归查询只匹配直接目录及 `目录/后代`；“播放全部”按当前稳定排序递归包含后代曲目。
- 文件夹一级页并列展示仅含当前可见音乐的存储卷卡片，以及全部非根、直接含至少一首当前可见曲目的音乐文件夹快捷项。主存储卷显示本地化“内部存储”，其他卷显示平台卷名称；存储卷卡片使用真实挂载路径和已用/总容量，容量读取失败时隐藏容量信息并保留卷卡片与可用导航。卷根直接含曲目时不额外生成快捷项。
- 音乐文件夹快捷项可位于任意深度，同一节点仍可从所属卷沿文件夹树逐级到达；快捷项的递归曲目计数和“播放全部”集合必须与进入该节点后的现有文件夹详情一致。快捷项搜索及固定 `0/A–Z/#` 索引只作用快捷项名称，不筛选存储卷卡片，也不把路径片段加入索引。
- 卷内中间页只展示名称升序的纯子目录卡片；直接含曲目的节点进入现有文件夹详情，继续使用既有曲目排序、可用性和播放入口。一级音乐文件夹快捷项与纯中间目录卡片不显示文件夹路径（包括重名快捷项）；现有文件夹详情内的目录行沿用既有展示约束，三点菜单只提供“播放全部”。

### 7.3 同步状态机

- 触发：首次授权、冷启动发现 MediaStore 版本或卷集合变化、前台内容变化、用户手动刷新。
- 应用前台注册 `ContentObserver`，以 `1 秒` 防抖合并变化并执行增量同步；同步期间的新变化只追加一次后继增量同步。
- 每次完整扫描创建同步代次，先 Upsert 本代发现曲目；全部查询与合并成功后，直接移除已挂载卷中本代未出现的缺失曲目并级联清理关联。
- 单曲失败继续扫描；整体查询失败保留旧缓存并展示错误。
- 不执行周期性后台扫描。

### 7.4 扫描界面

- 首次无缓存扫描使用全屏雷达和可访问的文字进度。
- 已有缓存时保留内容，仅显示非阻塞顶部进度。
- 首次及手动扫描完成后显示结果对话框；自动同步不弹窗。
- 结果按标题升序惰性展示全部成功曲目；不显示总数、成功数、跳过数或跳过项明细。
- 关闭结果对话框不影响已经原子提交的媒体库。
- 其余可排序页面独立记忆排序，标题、艺术家、专辑默认升序，添加时间默认最新优先，时长默认最短优先；艺术家集合页固定按名称升序且不提供集合页排序，艺术家详情页沿用详情页排序。
- 曲目批量操作包括加入歌单、加入队列、下一首播放和隐藏；任何操作均不物理删除音频。

### 7.5 元数据与封面

- 列表同步只读取 MediaStore 元数据；播放、详情、封面和歌词按需解析。
- 高级元数据与内嵌歌词后台并发上限为 2，请求对象变化或页面离开时取消。
- 解析与封面缓存键包含曲目标识和修改时间。
- ImageLoader 使用内存与磁盘 LRU；列表只请求目标尺寸缩略图。
- 艺术家集合页头像按曲目的 `TrackId` 稳定升序选择首张可用内嵌封面；没有可用内嵌封面时使用艺术家占位图。

## 8. 播放规格

### 8.1 服务与控制

- MediaLibraryService 托管单个 ExoPlayer 与 MediaSession。
- 本应用控制器可连接；受信系统控制器只获得标准浏览与播放命令；其他控制器拒绝。
- 外部控制器不开放队列编辑、播放模式切换或自定义业务命令。
- 任务被划走时，播放中继续；未播放允许服务停止。

### 8.2 三种互斥播放模式

- 模式仅包含列表循环、单曲循环、随机播放；首次启动默认列表循环。
- 列表循环：按原始队列顺序播放，队尾自然结束后回队首继续。
- 单曲循环：自然结束时重复当前曲目；手动上一首、下一首仍切换相邻曲目。
- 随机播放：保存原始队列并生成稳定随机序列；一轮结束后生成下一轮继续，避免两轮边界连续重复同一曲目。
- 退出随机播放时恢复原始顺序并保留当前曲目。
- 模式入口位于全屏播放器主控制区和队列页标题区，两处共享同一会话状态。

### 8.3 随机队列变更

- 播放队列允许同一曲目以不同队列项重复出现，每个队列项拥有独立身份；播放列表仍保持曲目唯一。
- 普通“加入队列”：追加到原始队列末尾，并随机插入当前随机序列的未播放区间。
- “下一首播放”：按选择顺序插入随机序列当前项之后，并追加到原始队列末尾。
- 已播放前缀和当前曲目保持不变。
- 播放队列在所有模式下均不提供拖拽排序。
- 移除当前曲目时从原始队列和随机序列同时删除并播放下一首；队列只剩该曲目时停止并清空当前曲目。

### 8.4 播放控制

- 点击曲目后立即显示当前项并进入准备态；准备超过 `300 ms` 才显示缓冲。
- 播放准备失败后恢复可操作状态。
- 快进、快退固定 `10 秒`，限制在 `0..duration`。
- 上一首始终切换当前播放顺序中的上一项，不先回曲首；位于队首时，列表循环跳到队尾，单曲循环保持队首，随机播放按稳定随机序列处理。
- 单曲准备或解码失败时标记本次播放不可用，显示曲名与资源化的简短原因并自动寻找下一首；遍历一轮仍无可播放项则停止。

### 8.5 淡出淡入

- 使用单个 ExoPlayer：前曲淡出至静音，切换媒体项，后曲淡入。
- 总时长 `0–2000 ms`、步进 `250 ms`、默认 `500 ms`；设置从下一次切歌生效。
- 自动切歌及手动上一首、下一首触发；暂停、恢复、Seek 和焦点变化不触发。
- 连续切歌采用最后一次指令生效，静音后只切到最后目标。
- 暂停、焦点丢失或私密输出断开时取消待切目标、恢复正常音量并暂停在已切换成功的曲目。
- 目标解码失败时保持静音寻找下一首，找到后淡入；遍历一轮失败则停止并恢复正常音量状态。

### 8.6 焦点、输出与历史

- ExoPlayer 自动管理音频焦点：短暂丢失暂停并在焦点恢复后自动继续，永久丢失后不自动恢复，允许系统自动降低音量。
- 私密输出断开立即暂停，重新连接不自动播放。
- 每次切入曲目创建播放实例；暂停、恢复、进程恢复延续实例，切换离开后再次进入创建新实例。
- 真实播放时间只在 Player 正在播放时累计；暂停、缓冲、Seek 跳过区间不计，重复片段照常累计。
- 达到 `min(30 秒, 曲目时长 50%)` 后该实例只增加一次历史次数。

### 8.7 快照、通知与恢复

- 队列变化、切歌、Seek、暂停、服务销毁时写入快照；播放中每 `5 秒` 更新位置和实例计时。
- 重开应用只恢复界面与断点，不自动播放。
- 系统媒体面板只显示上一首、播放暂停、下一首和元数据。
- 耳机和蓝牙按键使用 MediaSession 默认命令映射，不自行解释单双击或长按。
- 通知允许划除；划除时停止、保存快照、清空运行时队列、停止服务并撤销该会话的系统恢复卡片资格。
- 用户下一次主动播放后重新允许 Playback Resumption；系统恢复始终由用户操作触发。

## 9. 歌词规格

- 先在同目录同名 `.lrc`、内嵌 SYLT、内嵌 USLT 中选择带时间戳的来源，再按该顺序确定优先级；不使用在线服务。
- 支持 UTF-8、带 BOM 的 UTF-16、GB18030 回退、多时间标签与 `[offset:]`；坏行跳过。
- 三种来源均无时间戳时，外部 `.lrc` 有文本则作为静态歌词，否则使用原始内嵌文本；均无文本时显示 `lyrics_not_found`。
- API 29+ 未取得 SAF 目录授权时，外部 `.lrc` 仅通过 MediaStore 文件索引尽力读取；索引缺失或访问失败时按内嵌歌词与无歌词规则继续兜底，首版不新增目录授权流程。
- 静态兜底时清空三行同步歌词值。
- 当前行平滑居中；手动滚动暂停自动居中并显示“回到当前行”，停止操作 `5 秒` 后恢复；点击时间行 Seek。

## 10. UI 与导航规格

### 10.1 Navigation 3

- 九个一级路由：单曲、专辑、艺术家、歌单、播放历史、文件夹、扫描音乐、设置、关于。
- 每个一级路由维护可保存返回栈；点击侧边栏一级入口一律重置至该入口根页。
- 单曲、专辑、艺术家、文件夹、歌单中的最近选择项作为当前媒体浏览根页；应用操作页（扫描音乐、播放历史、设置、关于）返回该根页。
- 当前媒体浏览根页按返回将应用任务移至后台并回到桌面，播放服务与媒体通知保持运行。
- 播放器由位于当前一级栈之上的应用级 Player Sheet 承载；展开与折叠不修改 Navigation 3 返回栈，详情页进入所属一级栈。
- 窗口变化、语言重建和进程恢复不得丢失可保存导航状态。
- 导航跳转实行分层防抖与 Single-Top 幂等：`Navigator` 对目标路由与栈顶相同的重复压栈予以忽略；`commitNavigation` 前进跳转受 `300 ms` 时间窗口节流以对齐转场动效；返回操作不进行时间截断，保持即时响应。

### 10.2 自适应壳层

- `<600 dp`：窗口宽度 `50%` 的推移式侧栏，展开时主内容等距右移并由窗口边界裁切；主内容可见区域使用 `18%` 黑色遮罩并支持点击关闭。
- `600–839 dp`：固定宽度 `240 dp` 的常驻侧栏，不使用 Navigation Rail。
- `≥840 dp`：固定宽度 `256 dp` 的常驻侧栏。
- 三档窗口均使用三组圆角卡片：顶部快捷操作为退出、明暗模式、均衡器；媒体浏览组为单曲、专辑、艺术家、文件夹、歌单；应用操作组为扫描音乐、播放历史、设置、关于。
- 九个一级路由保持不变；侧边栏 Scan row 进入独立扫描页面，Tracks 页面不承载扫描交互，均衡器只显示后续版本提示。
- 导航项使用彩色图标，当前页通过 Tab 选中语义与清爽视觉呈现，不使用整行胶囊底色或额外侧边条。
- 退出按钮显示“完全退出、回到桌面、取消”：完全退出保存播放快照、停止播放服务并移除应用任务；回到桌面保留播放与媒体通知；取消不改变状态。
- 明暗模式按“跟随系统、浅色、深色”循环，并写入设置页使用的同一偏好。
- 单曲、历史、文件夹、队列、歌单及艺术家集合页使用单列。
- 专辑使用最小卡片宽度 `160 dp` 的自适应网格。
- 设置与关于最大宽度 `720 dp`；歌曲信息在紧凑窗口使用 Bottom Sheet，中等及展开窗口使用最大宽度 `640 dp` 的对话框。

### 10.3 播放器界面

- 曲目列表项固定 `72 dp`（文件夹列表项保留 `80 dp`），迷你播放器固定 `80 dp`；Mini 可见时应用壳层统一为业务内容保留 `80 dp` 底部空间。曲目列表项右侧常驻操作收拢为单一 48 dp 更多操作菜单按钮（包含添加到队列、下一首播放、加入歌单、隐藏等），消除行内按钮拥挤并保证触控区域与视觉整洁。
- 侧栏打开时 Mini 保持完整窗口宽度，位于侧栏和业务内容之上且继续响应操作；侧栏滚动区域同时预留 `80 dp`。
- 同一个应用级 Player Sheet 内重叠放置 Mini 与 Full 两层；折叠锚点露出 `80 dp` Mini，展开锚点铺满可用窗口，不提供隐藏态或半展开态。
- 点击 Mini 直接展开；纵向拖动时 Sheet 跟手移动，Mini 在进度 `0%–25%` 淡出，Full 在 `25%–100%` 淡入；不做封面连续缩放、共享元素形变或 Navigation 3 路由切换。
- 返回、全屏顶部下拉按钮或向下拖动将 Sheet 折叠并恢复原业务页面；展开及拖动期间禁用抽屉侧滑手势。
- 全屏页面顺序为封面、歌词、队列；进程内记忆页码，进程重启回封面。
- 全屏手势优先级为歌词/队列纵向滚动、子页横向翻页、Player Sheet 纵向折叠；列表到顶部继续下拉时移交 Player Sheet，列表底部继续上拉只做阻尼回弹。
- Mini 封面圆角从设计令牌读取：紧凑窗口 `16 dp`，中等与展开窗口 `20 dp`。
- Full Player 与艺术家集合头像使用圆形封面，其余封面为圆角矩形。
- Mini 与 Full Player 的播放、暂停、上一首、下一首及三种播放模式使用项目内 `ic_playback_*` 矢量资源；播放模式资源由单一 `PlaybackMode` 映射选择，切换模式不得依赖颜色区分。
- 队列支持移除和点击跳转，所有模式均不提供拖拽排序。
- 歌曲信息展示编码、比特率、采样率、文件大小和路径等元数据，只允许复制路径。
- 长按曲目进入多选，普通点击切换选择；全选只作用于当前筛选结果，返回键先退出多选，批量操作使用顶部上下文栏。

### 10.4 设计系统与可访问性

- 页面只从 `MusicDimensions`、`MusicShapes`、`MusicTypography` 读取间距、圆角、字号和固定高度。
- 业务图标使用项目内 Android `VectorDrawable`，保持中性路径颜色并由 `MusicTheme` 着色；图标图形规范统一采用 **Google Material Icons Round（圆角）** 体系（开源许可 Apache-2.0）及平滑圆角设计语言，杜绝直角/尖角几何图标（如播放、暂停、切歌等核心控件一律使用圆角平滑顶点）；资源 ID 按业务模型或稳定展示模型集中映射。
- 水平边距按紧凑、中等、展开使用 `16/24/32 dp`；卡片间距为 `12/16/20 dp`。
- 组件内部使用 `4 dp` 基准网格。
- 专辑网格卡片使用正方形封面和 `64 dp` 固定信息区；封面与卡片圆角在紧凑窗口为 `16 dp`，中等及展开窗口为 `20 dp`。
- 歌单页面布局基线：使用紧凑标题栏，标题区提供页级创建菜单；每个歌单以单列行展示方形封面、名称、曲目数和行级管理菜单（重命名、删除）。封面取最后加入且当前可用曲目的内嵌封面；该曲无内嵌封面或不存在可用曲目时显示封面占位图，无歌单时只显示居中空态插画。
- 专辑集合页为上述网格规则的页面特例：使用方形封面，封面外显示单行专辑标题和曲目数，不显示艺术家；右上角排序入口使用图标化表达，但保留现有排序字段、方向切换与持久化能力。
- 艺术家集合页是单列圆形封面行特例：每行显示艺术家名称和短曲目数，固定按名称升序且不提供集合页排序；右侧提供完整 `0/A–Z/#` 索引，支持点击和沿索引拖动定位，空标签只用于定位；艺术家详情页排序沿用既有规则。
- 艺术家名称在集合行中单行省略，其他标题最多两行；紧凑窗口标题为 `16/20 sp`、辅助文本为 `12/16 sp`，中等及展开窗口标题为 `18/22 sp`、辅助文本为 `14/18 sp`，分别对应列表/卡片；颜色使用 `onSurface` 与 `onSurfaceVariant`。
- 页面顶部栏（AppBar / Header）与分类头部标题字号统一使用 `titleLarge`（`22 sp`，行高 `28 sp`）；多选模式计数等辅助信息统一使用 `titleMedium`（`16 sp`，行高 `24 sp`）。
- 所有点击目标至少 `48 dp`；可交互图标使用中英双语字符串提供 TalkBack 语义；完整尊重系统字体缩放。
- 导航行与内容列表行的交互层必须占满所属内容窗格或分组卡片的整行宽度；视觉水平留白放在交互修饰符之后。分组卡片的首行和末行分别按卡片上、下圆角裁剪 ripple，行内独立操作按钮保留自己的点击目标。
- 垂直列表仅在可滚动内容到达真实顶端或底端后显示阻尼回弹；拖拽位移不超过视口高度的 `10%` 且上限为 `96 dp`，fling 上限为 `24 dp`。短列表、程序化滚动及系统动画缩放为零时不回弹；页面顶栏、Player Queue Header、右侧覆盖层、滚动条、Mini Player 与 Snackbar 始终锚定且不得被列表内容覆盖。
- Aero、封面和列表可绘制到系统栏后方，交互内容按 Insets 安全区避让。
- 系统栏图标明暗跟随当前主题，始终保持可读。
- 系统动画缩放为 0 时关闭页面、列表和 Aero 动画，扫描仍显示文字进度。
- 加载、空态和错误态使用共享组件；有缓存时保留内容并局部提示，错误态提供明确重试。
- Snackbar 固定在迷你播放器上方，同一时间只显示一条，其余顺序排队。
- 颜色不得作为唯一状态表达，图标按钮必须有语义标签；触觉只用于长按进入多选和关键模式切换。
- 所有单选项（Radio）、开关（Switch）与复选卡片统一遵循 [选项与开关组件开发规范](selection-and-toggle-controls.md)：整行/卡片可交互、带圆角容器先 clip、外层合并无障碍语义且内部子控件清除语义并置空回调、组件设为 internal 并具备自动化测试。

## 11. 主题、设置与关于

- Android 12+ 首次使用 Material You；低版本回退默认蓝。
- 提供默认蓝、翡翠绿、日落橙、紫罗兰四套完整 Light/Dark 色板。
- 明暗模式与应用语言首次跟随系统，Aero 默认光晕气场，淡出淡入默认 `500 ms`，扫描模式默认“扫描全部”，包含和排除目录初始为空。
- 主题、明暗、Aero 即时生效且不重建 Activity；语言切换允许重建并恢复状态。
- Aero 模式为流体网格、光晕气场、纯色静态。
- 动态 Aero 绘制在主应用壳层（包含一级与二三级页面）与全屏播放器背景，内容区域使用主题表面遮罩保证可读性。
- 基础 Material `surfaceContainer*` 颜色保持不透明；半透明是 Aero 页面持久卡片的显式语义，不由 `Card`、`Surface` 或页面位置自动继承。新增容器只有同时满足“页面内持久存在、具有卡片分组视觉、位于 Aero 背景上、明确需要透出背景”时才能选择该语义。
- 当前半透明允许清单为侧边栏分组卡片、设置页分组卡片、扫描页操作/开关/目录规则/说明卡片，以及文件夹页存储卷/快捷目录/中间目录卡片。动态 Aero 下初始 alpha 为 `0.5`；纯色模式或运行时降级为纯色时恢复不透明。
- `DropdownMenu`、自定义 Popup、Dialog/AlertDialog、Modal Bottom Sheet、Snackbar/消息气泡、Mini/Full Player Sheet 与其他未显式加入允许清单的容器保持不透明；透明卡片内部弹出的临时表面也不继承透明效果。
- 半透明卡片的普通文本对比度至少为 `4.5:1`，大文本与关键图标至少为 `3:1`；不达标时提高不透明度。视觉验收覆盖浅色/深色、预设色/动态取色、流体网格/光晕气场和纯色模式。
- 仅全屏播放器从当前封面提取最多三种主色并与主题色混合；其他页面始终使用当前主题色。
- 应用后台、屏幕关闭、省电模式或系统低电量事件成立时停止 Canvas 帧调度并使用纯色背景；条件全部解除且回到前台后恢复。
- 数据管理分别提供清空历史、删除全部播放列表、重建媒体库缓存；均需确认。
- 扫描使用启动时的路径规则快照，中途设置变化不影响本轮；保存路径规则后提示立即重扫，取消则保留新规则并标记待同步。
- 重置配置确认框明确列出保留数据；重建媒体库缓存不删除播放列表本身，成功完整同步确认的缺失曲目及其关联直接移除。
- 关于页从安装包读取版本，资源化展示开发者和致谢，许可由构建生成并离线展示。

## 12. 本地化、平台配置与备份

- 默认 `values/strings.xml` 为 English，`values-zh-rCN/strings.xml` 为简体中文。
- 启用 AGP 自动 LocaleConfig，并通过 `AppCompatDelegate.setApplicationLocales` 同步应用语言设置。
- 所有可见文本、通知文案和无障碍说明来自资源；数量使用 `plurals`，禁止拼接可见句子。
- 日期、数字、文件大小按当前应用语言格式化；时长使用本地化的 `mm:ss` 或 `h:mm:ss`。
- 只有启动 Activity 与受信 MediaLibraryService 可导出；不注册自定义 Deep Link、隐式业务 Intent 或导出 Provider，动态 Receiver 使用 `RECEIVER_NOT_EXPORTED`。
- 内部 Intent 显式；外部输入逐字段校验且不转发嵌套 Intent；PendingIntent 默认不可变。
- Auto Backup 只包含 DataStore 设置，排除数据库、队列、历史、播放列表和媒体库缓存。
