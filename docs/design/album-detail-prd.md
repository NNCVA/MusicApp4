## 1. 输入分层与产品定位

本次设计有四类输入，优先级如下：

1. **用户明确要求**是本页面的产品决策，包括 Hero 滚动标题、无页面级 `more`、无页面级排序、曲序优先、可选元数据、无封面曲目行、艺术家区块和自适应边界。
2. **附图**是窄屏竖屏视觉参考：用于确认透明系统栏、左侧返回按钮、横向 Hero、三列统计、曲目行、艺术家区块和底部 Mini Player 的相对位置与信息层级；图中的《八度空间》、周杰伦、时间、电量、歌曲名、编号和“18 首”等均为示例数据，不得写入代码或测试夹具。
3. **项目权威文档与现有架构**是实现约束：Room 是媒体库事实来源，专辑身份为“存储卷 + MediaStore Album ID”，播放由 `MediaController`/应用级 Player Sheet 承载，界面使用设计令牌和双语资源。
4. `grill-with-docs`、`grilling` 与 `domain-modeling` 只约束本次需求收敛、术语和决策记录流程，不属于产品功能。

本 PRD 是可开发、可验收的页面契约；本轮不改 Kotlin。当前实现缺口与实施边界见第 9.3 节和第 11 节。

> 视觉基线：本 PRD 以本轮用户提供的手机竖屏附图为准；系统状态栏和图中的专辑、歌曲、艺术家、时间、编号及数量只用于说明布局，不构成固定文案或测试数据。

## 2. 目标、用户价值与非目标

### 2.1 目标

- 让用户在不离开专辑上下文的情况下确认发行信息、音频质量、曲目顺序和参与创作的艺术家。
- 让专辑曲目按可靠的发行曲序播放；曲序缺失时仍提供确定、可复现的歌曲默认顺序。
- 保持附图的沉浸式 Hero 视觉，同时遵守 MusicApp 的 Aero、主题、Insets、可访问性和应用级播放器契约。
- 对缺失、混合、解析中或暂时不可用的数据诚实呈现，不用猜测值污染媒体库事实。

### 2.2 非目标

- 不提供专辑重命名、删除音频、编辑标签、在线补全元数据或在线封面。
- 不提供页面级 `more`、页面级排序、页面级搜索、页面级“播放全部”主按钮、拖拽排序或专辑详情多选模式。
- 不新增顶级导航入口，不复制实现 Mini/Full Player，不允许界面直接查询 MediaStore 或 DataStore。
- 不从文件名、目录名或截图文案推断碟号、音轨号、年份、位深或艺术家身份。

## 3. 页面结构与视觉布局

附图表现的是一个窄屏竖屏、深色主题下的静止初始态。下面的尺寸均为关系和视觉比例，落地时必须映射到设计令牌，不能把截图像素直接当作 `dp`；页面在更宽窗口仍保持同一信息顺序，不改成列表-详情双栏。

```text
应用壳层 / Aero 背景（深色主题表面遮罩）
└── AlbumDetailRoute(volumeName, mediaStoreId)
    ├── 透明系统栏后的固定顶部控制层
    │   └── [←] 返回（左侧，独立 48 dp 命中区）
    ├── 可滚动详情列
    │   ├── Hero 背景（封面低透明度模糊/渐变，不取色）
    │   │   └── 封面 + 专辑名 + 主艺术家 + 位深/采样率
    │   ├── 三列统计：曲目数 / 总时长 / 发行年份
    │   ├── 曲目列表
    │   │   └── 音轨号（或 ➖）+ 标题 + 质量角标/艺术家 + [⋮]
    │   └── 参与创作的艺术家
    │       └── 圆形头像/占位图 + 完整艺术家标签 + N 首
    └── 固定在底部的应用级 Mini Player
        └── 封面 + 当前曲目文本 + 播放/暂停 + 队列
```

### 3.1 画布、系统栏与顶部控制层

- 页面采用 edge-to-edge：系统状态栏透明，背景延伸到状态栏后方；系统栏图标按当前主题保持可读。
- 顶部控制层位于页面最上方安全区内，附图只显示左侧返回箭头，不显示页面标题、排序、更多或播放按钮。返回按钮视觉上靠左，交互目标至少 `48dp`，不得因为 Hero 滚动而消失。
- 只有详情列滚动；顶部控制层和底部 Mini Player 固定。详情列的首尾内容按状态栏、导航栏和 Mini Player Insets 避让。
- 背景从顶部 Hero 延伸到统计区域后逐渐过渡为深色主题表面，不能在曲目列表后继续产生高亮干扰。

### 3.2 Hero 滚动标题

- 静止且 Hero 仍在视口内时，TopBar 不显示标题文字；返回按钮始终显示。附图即为此状态。
- 当 Hero 的底部完全越过 TopBar 下缘后，TopBar 以淡入过渡显示当前专辑名；向下回滚重新进入 Hero 时反向淡出。
- 视觉上的空标题不等于无语义：TopBar 或页面根节点必须向 TalkBack 提供“专辑详情，专辑名”的可读语义。
- 专辑名缺失时使用本地化“未知专辑”；专辑身份存在但媒体库已无法提供曲目时使用“专辑不可用”状态文案。

### 3.3 Hero 视觉与布局

- Hero 从顶部控制层下方开始，先呈现一段覆盖全宽的封面背景：背景图放大、强模糊、低透明度并叠加深色遮罩；背景只营造层次，不作为可读内容，也不从封面取色改变主题。
- 主内容采用“左封面、右信息”的横向排版。封面为接近正方形的圆角矩形，左边缘与页面内容边距对齐；紧凑窗口以约 `128dp` 为基准，中等/展开窗口按可用宽度和令牌等比放大，不拉伸变形。
- 右侧信息按垂直层级排列：专辑名为最大、最醒目的标题；主艺术家紧随其下；最后显示两行音频技术信息，第一行位深（如 `16 bits`），第二行采样率（如 `44100 Hz`）。标题可最多两行，技术信息不得与标题重叠。
- Hero 不放置卡片边框、悬浮播放按钮或额外主操作；HQ/SQ/HR 质量角标只在曲目行出现。封面缺失、模糊失败、对比度不足或 Aero 降级时回退主题表面和统一占位图。
- 页面水平边距沿用紧凑/中等/展开 `16/24/32dp`；圆角、间距、字号和固定高度只读取 `MusicDimensions`、`MusicShapes`、`MusicTypography`。
- 仅全屏播放器保留封面取色能力；专辑详情不得复用该能力。

### 3.4 统计信息行

- 统计行紧接 Hero 横向信息块下方，使用三等分列；每列水平居中，列之间保持相同间距，不使用卡片或分隔线。
- 每列由两行组成：第一行是较大的高对比度数值，第二行是较小的本地化标签。固定顺序为“曲目数 / 总时长 / 发行年份”，标签为“歌曲 / 时长 / 年份”。
- 曲目数显示整数；总时长显示 `mm:ss`（超过一小时按全局时长格式化）；年份显示四位年份。任何字段无可靠值时仅该列显示 `➖` 及无障碍说明，不移动其他列。
- 统计行结束后留出令牌定义的垂直间距，再进入第一条曲目；统计背景与 Hero 的模糊层平滑衔接，曲目区域回到不透明深色表面。

### 3.5 曲目区域的视觉排版

- 曲目列表为单列、无图片、无外层卡片；行之间不绘制高对比度分隔线，以垂直留白和一致的基线形成节奏。
- 每行从左到右固定为“曲序栏 / 文本栏 / 行尾菜单”。曲序栏使用固定宽度并按令牌对齐，显示真实音轨号；附图中的 `2`、`3` 说明不能把列表位置重编号。
- 文本栏第一行是曲目标题，紧凑窗口优先单行省略；第二行由质量角标和完整艺术家标签组成。当前播放曲目标题使用主题主色强调，其他标题使用 `onSurface`；辅助文本使用 `onSurfaceVariant`。
- 行尾始终保留垂直三点菜单，图标视觉居中但命中区至少 `48dp`。曲序、标题、质量角标和艺术家共用整行播放命中区，菜单必须阻止点击冒泡。
- 曲目行固定使用项目的 `72dp` 行高令牌；不在行内追加时长、专辑图或第二个操作按钮。不可用曲目保留原位置并置灰，仍显示曲序和质量信息。

### 3.6 参与创作的艺术家区域

- 艺术家区域位于曲目列表之后，先留出明显的区块间距，再显示左对齐的“参与创作的艺术家”标题。标题使用主题主色或设计指定的浅蓝强调色，字号和字重高于条目辅助文本。
- 条目采用水平布局：左侧为圆形头像/占位图，右侧为两行文本，第一行完整艺术家标签，第二行为当前专辑内的 `N 首`。头像尺寸、圆角、条目间距全部来自设计令牌。
- 紧凑窗口按单列纵向排列；中等/展开窗口可在不压缩文本和命中区的前提下换列。没有可展示艺术家时隐藏整个区块，不显示空行。
- 只有稳定 Artist ID 的条目才提供导航语义；无稳定身份的条目保持相同视觉样式但仅为文本。

### 3.7 底部 Mini Player

- Mini Player 固定贴合窗口底部，使用不透明或高不透明度的深色表面、顶部细分隔线/阴影，并覆盖在详情列之上；详情列末项必须为它预留统一 `80dp` 底部空间。
- 内容从左到右为：小尺寸圆角专辑封面、当前曲目标题与第二行辅助文本、播放/暂停按钮、队列按钮。附图中的封面、曲名和副标题仅说明层级，不限定具体文案来源。
- Mini Player 不显示上一首/下一首等额外控制，也不复制 Full Player；播放按钮与队列按钮各自拥有至少 `48dp` 命中区，点击 Mini 主体按现有 Player Sheet 契约展开 Full Player。
- Mini Player 始终位于 Snackbar 下方或由 Snackbar 按全局规则避让；详情列滚动、Hero 标题淡入和返回操作不改变 Player Sheet 返回栈。

## 4. Hero 信息契约

### 4.1 首版稳定信息

| 信息 | 展示规则 | 数据口径 |
|---|---|---|
| 专辑名 | 主标题，最多两行，超出省略 | 当前 `AlbumId` 对应曲目中的稳定专辑名；缺失回退“未知专辑” |
| 主艺术家 | 专辑名下方显示 | 依据曲目默认顺序取可稳定识别的主艺术家；无值显示本地化未知艺术家 |
| 位深 | Hero 技术信息第一行，格式化为 `N bits`；无值显示 `➖` | 专辑所有保留曲目均有相同有效值时才形成摘要 |
| 采样率 | Hero 技术信息第二行，格式化为 `N Hz`；无值显示 `➖` | 专辑所有保留曲目均有相同有效值时才形成摘要 |
| 曲目数 | 固定统计单元 | 当前专辑保留的曲目条目数，包含暂时不可用曲目 |
| 总时长 | 固定统计单元 | 所有保留曲目的 `durationMs` 总和，按当前语言格式化 |
| 发行年份 | 固定统计单元 | 专辑所有可用发行年份均存在且相同；存在冲突时显示 `➖` |

附图中的 HQ/SQ 质量角标不在 Hero 单独汇总，只在对应曲目行的第二行显示；曲目数、总时长与发行年份组成 Hero 下方的三列统计行。

曲目数与总时长描述媒体库事实；本页面不提供“播放全部”主按钮，点按曲目或应用级 Mini Player 承担播放入口。

### 4.2 可选技术与发行元数据

下列字段均进入 `AlbumTechnicalSummary`，但首版窄屏 Hero 只占用位深和采样率两行；编码、比特率不额外增加第三行，优先在“歌曲信息”中查看。更宽窗口若确需展示，也必须复用同一技术信息块并保持标题、艺术家和统计行的层级，不新增浮层卡片。所有实际渲染的字段均遵循：有可靠值显示格式化值；没有值、解析中、解析失败、值冲突或数据不完整时显示 `➖` 图标。图标必须有本地化无障碍描述，不得仅靠图形表达状态。

| 字段 | 可靠值条件 | 本页布局位置（示例仅示意） |
|---|---|---|
| 编码 | 专辑所有保留曲目均可解析且归一化后相同 | 首版 Hero 不单独占行；在歌曲信息中显示 FLAC |
| 比特率 | 专辑所有保留曲目均有相同有效值 | 首版 Hero 不单独占行；在歌曲信息中显示 1411 kbps |
| 采样率 | 专辑所有保留曲目均有相同有效值 | Hero 第二行，例如 `44100 Hz` |
| 位深 | 专辑所有保留曲目均有相同有效值；当前解析层缺失时显示 `➖` | Hero 第一行，例如 `16 bits` |
| 发行年份 | 专辑所有可用发行年份均存在且相同；存在冲突时显示 `➖` | 三列统计的第三列，例如 `2002` |

“混合技术元数据”不显示“多种”长文本，统一使用 `➖`，避免 Hero 变成诊断面板；无障碍描述可补充“专辑内存在多个值”。技术信息按需解析，解析延迟不能阻塞 Hero、曲目列表或播放。

## 5. 曲目列表

### 5.1 排序与曲序

页面不显示排序入口，也不保存专辑详情排序状态。排序规则固定为：

1. 曲目具有有效 `discNumber >= 1` 与 `trackNumber >= 1` 时，按“碟号升序 → 音轨号升序”排列；单碟专辑视觉上可隐藏碟号。
2. 全部曲目都没有有效曲序时，使用歌曲默认排序：标题升序，大小写归一化，最终以 `TrackId(volumeName, mediaStoreId)` 稳定打破平局。
3. 只有部分曲目有号、出现重复号或出现无效号时，有效且不冲突的曲序项先按曲序排列；无号、重复或冲突项置于后段，按歌曲默认排序排列。冲突项不伪造编号。
4. 曲目号缺失时左侧固定槽位显示 `➖`；曲目号有效时显示真实号。多碟或 `discNumber > 1` 时显示 `碟号-音轨号`（例如 `1-02`），不得把列表位置当成音轨号。

上述规则是专辑详情页对全局可排序分类页的明确特例，详见 ADR-0015。

### 5.2 曲目行

- 每行固定 `72dp`，不显示曲目图片；左侧固定宽度显示真实曲序或 `➖`，不能用列表位置重新编号。
- 中部显示曲目标题、质量角标和完整艺术家标签；紧凑窗口标题优先单行省略，第二行固定给质量角标与艺术家标签。
- 当前播放曲目的标题使用主题主色强调；质量角标保留 `HR`、`HQ`、`SQ` 等文字，颜色只作辅助，不得作为唯一状态表达。
- 行内不显示单曲时长，以保持附图的信息密度；单曲时长通过“歌曲信息”查看。
- 普通点击整行播放该曲目，并以当前专辑的已排序曲目集合建立 `PlaybackContext`；暂时不可用曲目置灰、不可播放并显示状态语义。
- 不支持长按进入多选，不显示选择框，不提供专辑详情批量操作。
- 保留歌曲行尾 `⋮`，复用全局行级管理菜单：加入队列、下一首播放、加入歌单、隐藏和歌曲信息等既有能力；菜单不提供物理删除或编辑音频标签。
- 行尾菜单和整行点击必须保持独立命中区：点击 `⋮` 不触发播放，所有目标至少 `48dp`。

### 5.3 页面级播放入口

- 附图没有 Hero 下方的“播放全部”按钮；本版详情页不插入该主操作，也不新增随机播放、排序或页面级 `more`，避免破坏“封面/统计/曲目”连续纵向节奏。
- 播放入口只有曲目行点击和应用级 Mini Player。若产品后续仍需批量建队，应从已有统一列表或行级菜单进入，不能在本页新增一块视觉按钮。
- 播放队列仍使用当前固定曲序；暂时不可用曲目跳过并通过现有消息反馈机制告知数量，空专辑或没有可用曲目时不替换现有队列。

## 6. 参与创作的艺术家

- 区块标题本地化为“参与创作的艺术家”，左对齐页面内容边距并使用主题主色/设计指定的浅蓝强调色；标题与最后一条曲目之间保留明显的垂直间距。没有可展示艺术家时省略整个区块，不显示空占位行。
- 从当前专辑曲目中读取**完整艺术家标签**并去重；不按 `/`、`;`、`feat.` 等分隔符拆分。
- 展示顺序为当前曲目顺序中的首次出现顺序；曲目顺序回退时沿用回退后的列表顺序。
- 每项展示圆形头像或占位图、完整艺术家名和 `N 首`；条目为左图右文的两行水平布局，`N` 是该完整标签在当前专辑中的曲目数，包含暂时不可用曲目，不是艺术家全库曲目数。附图中的“18 首”仅为示例，不代表固定统计值。
- 只有存在稳定 Artist ID 的条目可点击并进入 `ArtistDetailRoute`；仅有名称或无法稳定解析身份时保留文本，不提供点击语义。
- 现有“按名称包装 ArtistId”与合作标签拆分实现需要在 UI 接入前修正为稳定身份契约；本 PRD 不允许通过名称猜测路由身份。

## 7. 导航、播放器与自适应

### 7.1 导航

- 使用已有 `AlbumDetailRoute(volumeName, mediaStoreId)`，归属 Albums 一级栈；返回回到进入详情前的专辑集合上下文。
- 页面不新增 Deep Link，不改变 `AlbumId` 的存储卷隔离，不把专辑名直接编码为路由身份。
- 页面级不提供 `more`、排序、搜索、播放全部或额外页头菜单；附图顶部只保留返回箭头。

### 7.2 应用级播放器

- Mini/Full Player 由应用级 Player Sheet 统一承载；详情页不复制播放器 UI。
- 页面为底部 Mini Player 预留统一 `80dp` 空间；播放器存在时列表末项、艺术家区块和 Snackbar 不被遮挡。
- 附图中的 Mini Player 为全宽底部固定条，依次放置小封面、当前曲目标题/辅助文本、播放（或暂停）按钮和队列按钮；不在详情页增加上一首/下一首等重复控制。
- Hero/列表滚动不改变 Player Sheet 返回栈；播放控制继续只通过 `PlaybackControllerFacade`/`MediaController`。

### 7.3 窗口与 Insets

- `<600dp` 使用附图的紧凑单页结构：Hero 保持封面与信息横排，统计保持三等分，曲目与艺术家为单列；`600–839dp` 和 `≥840dp` 扩大 Hero 可用宽度、允许艺术家条目换列，但仍是一个全屏详情路由，不引入列表-详情多窗格。
- 系统栏后方可绘制背景，返回按钮、Hero 首尾内容、列表末项和播放器按 Insets 避让。
- 背景模糊、列表回弹和标题淡入在系统动画缩放为零、后台、省电或低电量时按全局降级规则停用或回退静态表面。

## 8. 状态、错误与空态

| 状态 | 页面行为 |
|---|---|
| 首次媒体库投影未就绪 | 不显示“此专辑为空”或“暂无专辑”；沿用启动门控/缓存优先规则，待首批有效投影后判定 |
| 专辑存在且有曲目 | 显示完整 Hero、曲目列表和艺术家区块；技术字段可逐项显示值或 `➖` |
| 专辑存在但没有曲目 | 显示 Hero 可用信息和“此专辑为空”空态；不伪造曲目数或播放队列 |
| 专辑 ID 已无法从已就绪媒体库找到 | 显示“专辑不可用”状态并保留返回；不把路由参数当作专辑名 |
| 专辑仅含暂时不可用曲目 | 保留曲目数、总时长、Hero 和置灰列表；播放入口禁用，行不触发播放 |
| 单曲高级元数据解析失败 | 不替换已加载列表；对应 Hero 字段保持 `➖`，记录可诊断错误但不打断用户操作 |
| 封面缺失 | 使用 `ic_playlist_album` 或统一专辑占位图；背景回退主题表面 |
| 媒体库观察流短时失败且有缓存 | 保留上一份内容，按全局错误反馈显示重试/状态，不瞬间清空详情 |

## 9. 数据与实现契约

### 9.1 建议的领域投影

页面需要一个由 Room 曲目事实和按需元数据解析派生的专辑详情投影，概念上包含：

| 投影 | 必需字段 |
|---|---|
| `AlbumDetail` | `AlbumId`、专辑名、主艺术家、曲目列表、曲目数、总时长、质量标签集合、技术摘要、艺术家署名集合 |
| `AlbumTrackPresentation` | `TrackId`、标题、完整艺术家标签、`discNumber?`、`trackNumber?`、质量、可用性、曲序冲突标记 |
| `AlbumTechnicalSummary` | `encoding?`、`bitrateBps?`、`sampleRateHz?`、`bitDepth?`、`releaseYear?`，以及缺失/混合/解析失败状态 |
| `AlbumArtistCredit` | 完整艺术家标签、稳定 Artist ID（可空）、当前专辑曲目数、头像请求身份（可空） |

这些是 PRD 数据契约，不要求本轮直接创建同名 Kotlin 类型；字段可空性和冲突状态必须在实现与测试中可观察。

### 9.2 数据源与性能

- 专辑与曲目基础数据只从 Room `tracks` 派生；UI 不直接查询 MediaStore。
- 封面、编码、比特率、采样率、位深、年份、碟号和音轨号按需解析；解析结果缓存键包含曲目标识和修改时间。
- 高级元数据解析遵循后台并发上限 `2`，请求对象变化或页面离开时取消；解析中先显示 `➖`，不阻塞列表首帧。
- 封面请求复用 `AlbumArtworkRequest`/统一 ImageLoader 和占位资源；详情 Hero 不解码无限制原始大图。
- 播放建队复用 `CategoryPlaybackContextFactory` 的可用性过滤和稳定 `AlbumId` source ID。

### 9.3 当前实现缺口

- `AlbumDetailUiState` 尚无封面、技术摘要、艺术家署名、总时长、曲序和加载/错误状态。
- `Track`、扫描候选和当前高级元数据模型尚无 `releaseYear`、`discNumber`、`trackNumber`、`bitDepth`；需要扩展解析与持久化/投影边界。
- 当前详情仍由 `CategoryHeader` 提供“播放全部”和 `CategoryTrackSortMenu` 排序入口，并使用 `CategoryTrackList`；需移除这些页面级入口并实现附图的曲序优先列表。
- 当前列表没有专辑曲序、质量角标和行尾管理菜单；可复用 `QualityBadge`、`TrackActionsMenu` 与既有消息/歌曲信息组件。
- 当前艺术家路由和分组仍存在名称身份、合作标签拆分差距；稳定 Artist ID 契约是艺术家点击的前置条件。
- 本项目现有实现规格对“其余详情页可排序”有通用描述；专辑详情按本 PRD 与 ADR-0015 执行特例，其他页面不受影响。

## 10. 本地化、可访问性与验收

### 10.1 本地化与无障碍

- 所有标题、状态、数量、质量标签、元数据标签、菜单和内容描述进入 `values/strings.xml` 与 `values-zh-rCN/strings.xml`；数量使用 `plurals`。
- `➖` 的视觉图标不承载唯一状态语义；TalkBack 读出字段名及“无数据/未提供/专辑内存在多个值”等本地化描述。
- Hero 视觉空标题时，页面语义仍包含专辑名；返回、行尾菜单、艺术家项和占位封面均提供明确 content description。
- 完整尊重系统字体缩放；标题、艺术家名和技术信息在固定高度中按规则省略或换行，不裁切点击目标。

### 10.2 验收场景

| 编号 | 场景 | 验收结果 |
|---|---|---|
| A-01 | Hero 初始可见 | 透明系统栏下方只有返回按钮；Hero 以左封面/右信息横排显示专辑名、主艺术家和两行技术信息 |
| A-02 | Hero 完全滑出 | TopBar 淡入专辑名；回滚后淡出；TalkBack 始终可读 |
| A-03 | Hero 下方统计 | 三等分居中显示曲目数、`mm:ss` 总时长和四位发行年份，各自为数值行+标签行 |
| A-04 | 全部曲目有曲序 | 按碟号/音轨号排列，显示真实编号；单碟不强制显示碟号 |
| A-05 | 无曲序 | 按标题默认升序和稳定 TrackId 排列，左侧每行显示 `➖` |
| A-06 | 部分/重复/无效曲序 | 有效不冲突项在前，异常项稳定置后；异常项不猜号 |
| A-07 | 技术字段缺失或混合 | Hero 位深/采样率槽位各自显示 `➖`，不阻塞列表，不显示猜测值 |
| A-08 | 质量混合 | HR/HQ/SQ 质量角标仅出现在对应曲目行第二行，按稳定顺序去重 |
| A-09 | 暂时不可用曲目 | 统计保留，行置灰，播放跳过或禁用；不从页面删除 |
| A-10 | 歌曲行交互 | 无图片、无长按多选；整行播放；`⋮` 菜单不冒泡触发播放 |
| A-11 | 艺术家署名 | 标题左对齐且使用强调色；条目为圆形头像+两行文本；有稳定 ID 可进入详情，无 ID 纯文本 |
| A-12 | 主题/背景 | 背景不取色；对比度不足或 Aero 降级时回退主题表面 |
| A-13 | Mini Player 可见 | 全宽底部固定条显示封面、两行文本、播放/暂停和队列；列表末项、艺术家区块和 Snackbar 不被遮挡 |
| A-14 | 中等/展开窗口 | Hero 变宽、艺术家可换列但仍为单一全屏详情，不出现多窗格压缩 |
| A-15 | 首次未就绪/专辑缺失 | 未就绪不误判空态；缺失显示明确不可用状态并可返回 |

### 10.3 测试分层建议

- `app/src/test`：曲序合法性、碟号/音轨号排序、异常回退、技术摘要聚合、质量标签去重、艺术家完整标签去重与计数、播放上下文顺序。
- `app/src/androidTest`：真实 Room 投影、元数据/封面解析取消与缓存、Hilt 图、资源与无障碍语义、Navigation 3 返回和 Player Sheet 底部避让。
- 设备/视觉验收：紧凑、中等、展开窗口；浅色/深色、Aero/纯色、系统字体放大、无封面、混合技术字段和暂时不可用曲目。截图中的示例数据不作为断言值。

## 11. 决策与后续实施顺序

已冻结的决策：

1. Hero 初始视觉无 TopBar 标题，Hero 完全滑出后显示专辑名。
2. 页面级无 `more`、无排序、无“播放全部”主按钮；专辑详情曲序优先，缺失时使用歌曲默认排序。
3. Hero 稳定信息为专辑名、主艺术家、位深和采样率；曲目数、总时长、发行年份组成下方三列统计；技术/发行字段逐项值或 `➖`。
4. 曲目行无图片、无长按多选；左侧为真实曲序或 `➖`；标题与质量角标/艺术家分两行；保留行尾 `⋮`。
5. 艺术家按完整标签去重，计数限定当前专辑；只有稳定 Artist ID 可导航。
6. 详情保持全屏路由，允许不可取色的低透明度封面模糊/渐变；底部使用应用级 Mini Player；自适应不拆多窗格。

实施顺序建议：先补齐曲序/发行元数据与稳定艺术家身份，再建立 `AlbumDetail` 投影和 ViewModel 状态，随后实现 Hero/曲目行/艺术家区块，最后补资源、无障碍、Room/导航/设备验收。任何需要改变专辑身份、曲序回退或技术字段可靠性定义的改动，应先更新本 PRD 与 ADR-0015。
